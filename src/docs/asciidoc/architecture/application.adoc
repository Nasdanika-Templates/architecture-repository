[#application]
= Application Architecture

_C4 levels 2 and 3. ADM Phase C._

The application architecture follows the recommended solution pattern, a custom retrieval-augmented
orchestrator (<<solution-patterns>>), which is [.proposed]#PROPOSED# in <<adr-002>>. If the managed
agent service is chosen instead, the Chat Orchestrator is largely replaced by configuration of that
service, and the rest of this chapter stays.

----

The existing Web Application and database of the C4 example are unchanged and left out of the
diagram. The API Application gains read-only endpoints shaped for the assistant's tools: recent
transactions with merchant and fee details, account summaries, card status. They reuse the
existing authorization: the orchestrator passes the customer's token, and never holds a credential
of its own that could read another customer's data (<<adr-005>>).

[#chat-flow]
== Answering a Question

<<chat-sequence>> shows the main flow, for a question that needs both approved content and the
customer's own data.

[#chat-sequence]
.Answering "Why was I charged $15 on 2 October?"
[plantuml,chat-sequence,svg,pdfwidth=100%]
----
actor Customer
participant "Single-Page\nApplication" as SPA
participant "Chat\nOrchestrator" as O
participant "Content\nSafety" as CS
participant "Content\nIndex" as IX
participant "Azure\nOpenAI" as AOAI
participant "API\nApplication" as API

Customer -> SPA: Why was I charged $15 on 2 October?
SPA -> O: message, customer session
O -> CS: screen input (prompt shield)
CS --> O: allowed
O -> IX: hybrid search "fee charged"
IX --> O: passages: fee schedule
O -> AOAI: question, passages, tool definitions
AOAI --> O: call getTransactions(date=2 Oct)
O -> API: GET transactions, customer token
API --> O: "Overdraft fee $15"
O -> AOAI: tool result
AOAI --> O: answer with citations
O -> CS: screen output, check grounding
CS --> O: allowed
O --> SPA: streamed answer, citations
SPA --> Customer: "It was an overdraft fee: ..." + link to fee schedule
----

If the input is blocked, the topic is sensitive, the grounding check fails or the model asks for a
tool it is not allowed to call, the orchestrator does not answer from the model: it offers a human
and, with the customer's consent, hands over.
