When an item is confirmed, its status becomes [.fact]#FACT# with the source, and the commit that

[#environments]
== Environments and Networking

* Development, test, pre-production and production, each with its own Azure OpenAI deployments and
  index, so that evaluation runs never touch production quotas.
* All Azure services are reached through private endpoints; public network access is disabled.
* The orchestrator is reachable only through the bank's existing API gateway, which fronts the
  {system}.
* Model deployments use the bank's chosen deployment type for data residency, for example a
  regional or data-zone deployment, as approved by Information Security (<<oq-02>>).

[#operations]
== Operations

Monitoring::
Latency, token usage and cost per conversation, handover rate, content filter hits, grounding check
failures and customer feedback, on the bank's monitoring platform. Message text stays out of
telemetry (<<data-principles>>).

Capacity::
Azure OpenAI quota per deployment, sized from the expected peak conversations per minute
(<<a-06>>), with provisioned throughput considered once usage is known.

Model lifecycle::
Model versions are retired by the provider on a published schedule. Each upgrade is a change: the
evaluation suite runs against the new version, and the results are recorded before the switch
(<<evaluation-plan>>).

Fallback::
If the model is unavailable or too slow, the chat says so and offers the contact center. There is
no silent fallback to a different, unevaluated model.
