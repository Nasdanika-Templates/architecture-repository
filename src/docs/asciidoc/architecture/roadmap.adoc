[#sample-pocs]
== Proofs of Concept

Phase 0 closes its decisions with evidence, not with more judgment. Each proof of concept answers one
question, is built and published as described in <<pocs>>, and feeds an evaluation or an
assumption. None has run yet; the scores they will replace are the drafted ones in
<<alternatives>>.

[cols="1,4,3,3",options="header"]
|===
|ID |Question |Feeds |Lives in

|[[poc-1,POC-1]]POC-1
|Which embedding model retrieves the right passages for real customer questions, on the bank's own
content? Recall at 5 on the golden question set, per model, at the reduced and full dimensions.
|The retrieval scores in <<embedding-models>>; <<adr-003>>; <<oq-06>>
|This repository, `poc/retrieval/`, run by the build against recorded embeddings (<<recorded-runs>>)

|[[poc-2,POC-2]]POC-2
|How grounded, correct and fast is each chat model on the golden set, in the bank's region and
deployment type?
|The groundedness, quality and latency scores in <<chat-models>>; <<adr-004>>; <<a-08>>
|The evaluation harness (WP-6), its own repository, which publishes versioned results that this
build unpacks

|[[poc-3,POC-3]]POC-3
|Can the Contact Center Platform accept a chat from an external channel, with the conversation so
far?
|<<a-04>>; <<adr-002>>
|The contact center team's repository, a source dependency at a tag
|===

[#implementation-governance]
== Implementation Governance

* *Architecture contract.* The DECIDED ADRs are the contract with the delivery teams. A change in
  delivery that contradicts one needs a new ADR, not a quiet workaround.
* *Compliance reviews.* At each phase exit, the architects compare what is built with this document,
  helped by the snapshots of the deployed resources (<<across-systems>>), and record the differences
  as findings, decisions or dispensations in <<decision-log>>.
* *Versions.* The version of this document approved at each phase exit is tagged.
