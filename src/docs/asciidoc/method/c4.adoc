[#c4]
= C4 Model Alignment

The C4 model, by Simon Brown, describes software architecture with a small set of abstractions and
four levels of zoom. It is easy to learn, notation-light and increasingly the common language of
architecture diagrams. The document uses it for every structural diagram.

[#c4-levels]
== Levels and Where They Live

[cols="1,3,2"]
|===
|Level |Shows |In this document

|1. System Context
|The system, its users and the systems it depends on.
|<<context>>

|2. Container
|The applications and data stores that make up the system, and how they communicate.
|<<application>>

|3. Component
|The components inside one container.
|<<application>>, for the containers that the project builds.

|4. Code
|Classes and functions. Rarely worth drawing by hand; generate it if needed.
|Not used.
|===

The supplementary diagrams fit too: a _dynamic_ diagram, or a sequence diagram, for an important
flow (<<chat-flow>>), and a _deployment_ diagram for the technology architecture (<<technology>>).

[#c4-as-code]
== Diagrams as Code

The diagrams are PlantUML with the C4-PlantUML library, which ships with PlantUML. A container
diagram looks like this:

[source,text]
----
!include <C4/C4_Container>

Person(customer, "Personal Banking Customer")
System_Boundary(ibs, "Internet Banking System") {
  Container(spa, "Single-Page Application", "JavaScript, Angular")
  Container(chat, "Chat Orchestrator", "Python, FastAPI")
}
Rel(customer, spa, "Uses", "HTTPS")
Rel(spa, chat, "Sends messages to", "JSON/HTTPS")
----

The build renders the diagrams, so they cannot drift from their source, and an assistant can draft
and update them like any other text. Ask for one level at a time, and review the picture as well as
the diff: layout problems show only in the picture.

C4 diagrams map to TOGAF's views. The context diagram belongs to the Architecture Vision, the
container and component diagrams to the application architecture, and the deployment diagram to the
technology architecture (<<togaf>>).
